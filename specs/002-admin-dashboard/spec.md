# Feature Specification: Operational Admin Dashboard & Management UI

**Feature Branch**: `feature/admin-dashboard`
**Created**: 2026-11-13
**Status**: Draft (Updated post-audit)
**Target Component**: Commerce Integration Hub (CIH)

---

## 1. Problem Statement

Commerce Integration Hub работает как автономный фоновый сервис интеграции 1C CommerceML. До настоящего момента оперативное наблюдение, отладка инцидентов и проверка состояния каталога требовали:
1. Запуска CLI-команд (`monitor:status`, `messenger:consume`, `app:cml:publish-outbox`) внутри Docker-контейнеров.
2. Прямых SQL-запросов к PostgreSQL (`import_runs`, `products`, `product_variants`, `import_run_outbox`, `messenger_messages`).
3. Отсутствовал наглядный веб-интерфейс для дежурного инженера и администратора для мгновенного контроля:
   - Интегрального статуса работоспособности (`HEALTHY`, `DEGRADED`, `CRITICAL`);
   - Зависших или упавших импортов CommerceML с детальным анализом санитизированных ошибок (`errorMessage`);
   - Задержек публикации транзакционного Outbox и бэклога очередей Messenger;
   - Синхронизированных цен и складских остатков по номенклатуре.

## 2. Business & Engineering Goals

1. **Единый центр оперативного управления**: Предоставить защищенный веб-интерфейс для непрерывного мониторинга и навигации по ключевым сущностям системы без прямого доступа к shell/SQL.
2. **Строгая Read-Only безопасность**: Исключить случайное или несанкционированное изменение данных, состояния очередей или сброс CAS-токенов через UI на этапе мониторинга. Запросы выполняются в read-only режиме транзакций СУБД с безопасным жизненным циклом (`BEGIN` -> `SET TRANSACTION READ ONLY` -> `SELECT` -> `COMMIT`/`ROLLBACK`), без каких-либо SQL-запросов до команды `SET`. Вызовы `flush()` категорически исключены. Разрешены исключительно безопасные HTTP-глаголы (`GET`, `HEAD`), любые модифицирующие запросы (`POST`, `PUT`, `DELETE`, `PATCH`) блокируются с кодом `405 Method Not Allowed`.
3. **Защита открытого порта 8080 и изоляция `/cml/**`**:
   - Маршруты обмена 1C (`/cml/**`) обрабатываются бандлом `faustddd/symfony-1c-import` с собственной аутентификацией; в `security.yaml` для них объявляется приоритетный файрвол `cml: { pattern: ^/cml, security: false }`.
   - Маршруты админки (`/admin/**`) закрываются изолированным файрволом `admin: { pattern: ^/admin, http_basic: ... }` с защитой от brute-force (`login_throttling`), аутентификацией по `ADMIN_USER` и `ADMIN_PASSWORD_HASH` (bcrypt/argon2id, без открытых паролей в `.env`), и строгим требованием TLS через trusted proxy (`framework.trusted_proxies` и `trusted_headers`).
4. **Минимальное влияние на СУБД (Zero Degradation)**: Выборки для UI не должны вызывать длительных блокировок или деградации обработки импортов. Использовать строгие `statement_timeout` (250ms для мониторинга, до 1000ms для каталога), двухфазную пагинацию (ID scan + hydration) во избежание N+1 и деградации производительности в Doctrine ORM 3.7 / DBAL 4.

## 3. High-Level Requirements

### 3.1 Функциональные разделы панели
1. **Dashboard (`/admin`)**:
   - Карточки статуса системы (`HEALTHY`/`DEGRADED`/`CRITICAL`), активные аномалии.
   - Сводные метрики очередей: бэклог `async_catalog`, `async_offers`, счетчик `failed`.
   - Метрики Outbox: непубликованные сообщения, максимальный лаг доставки.
   - Список активных (`PENDING`/`PROCESSING`) и последних завершенных импортов.
2. **Импорты (`/admin/imports` и `/admin/imports/{id}`)**:
   - Постраничный реестр запусков импорта (`ImportRun`) с фильтрацией по типу (`catalog`/`offers`) и статусу.
   - Детальный экран запуска: время выполнения, попытки (`attempt`), fencing token, метаданные файла, связанный outbox и санитизированный стек-трейс ошибки (`errorMessage`).
3. **Каталог товаров (`/admin/products`)**:
   - Реестр номенклатуры (`Product`) с поиском по SKU и внешнему ID 1C.
   - Двухфазная пагинация без искажения лимитов Doctrine ORM 3: выборка идентификаторов `id`, затем точечная гидратация с коллекцией вариантов `variants`.
   - Список вариантов (`ProductVariant`): цены в рублях (конвертация копеек из `price_amount`), складские остатки со строгой точностью `stock` (NUMERIC 14, 3).
4. **Очереди и Outbox (`/admin/queues`)**:
   - Детализация по очередям Symfony Messenger (`async_catalog`, `async_offers`, `failed`).
   - Анализ сообщений в `import_run_outbox` (отложенные `defer`, повторы `retry`, непубликованные пачки).
5. **Диагностический API (`/admin/api/health`)**:
   - Легковесный JSON-эндпоинт для автообновления виджетов дашборда без перезагрузки всей страницы.

### 3.2 Нефункциональные требования и безопасность
- **Стек UI**: Twig 3.x, Symfony TwigBundle 7.4+, чистый адаптивный CSS без внешних сборщиков. Twig auto-escaping включен по умолчанию для всех строковых данных из 1C.
- **Безопасность**: `symfony/security-bundle 7.4+`, файрвол с Basic Auth, rate limiting (ограничение частоты запросов к `/admin`), принудительный TLS через заголовки прокси (`X-Forwarded-Proto`), хранение только хэша пароля `ADMIN_PASSWORD_HASH`.
- **СУБД**: Все запросы контроллеров выполняются внутри транзакций `READ ONLY` (последовательность `BEGIN` -> `SET TRANSACTION READ ONLY` -> `SELECT` -> `COMMIT`/`ROLLBACK`), вызовы `flush()` запрещены на уровне архитектурного контракта.
- **Конфиденциальность**: Обязательная санитизация строк ошибок через существующий `MonitoringDataSanitizer` (сокрытие паролей, DSN базы, путей хоста, персональных данных).

## 4. Edge Cases & Risks
- **Попытки брутфорса Basic Auth на открытом порту 8080**: Парируются rate limiter (например, 10 попыток в минуту на IP) и работой за обратным прокси с TLS.
- **XSS через данные CommerceML**: Наименования и реквизиты номенклатуры могут содержать неэкранированные спецсимволы и теги; стандартное автоэкранирование Twig блокирует вектор атаки.
- **Искажение лимитов OneToMany в Doctrine ORM 3**: Исключается двухфазной выборкой (ID-first пагинация).
